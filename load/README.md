# Phase 2a — Load the Open Food Facts file into Snowflake

Result: table `GODESI_RAW.OPEN_FOOD_FACTS.PRODUCTS` with 26,293 rows, 211 source columns
(all `VARCHAR`) plus 3 load-metadata columns. About 20 minutes.

Files:
- `load/01_load_open_food_facts.sql`: the SQL to run (generated by `scripts/build_off_load_sql.py`)
- `data/raw/off_india_raw.tsv.gz`: the file to upload (8 MB, gzip of `off_india_raw.tsv`)

## Steps

### 1. Open the SQL in Snowflake
Open `load/01_load_open_food_facts.sql` in VS Code or Notepad, copy everything, and paste it
into a new Snowflake worksheet. The file is long (743 lines) because it lists every column.

### 2. Create the file format and stage
Run **sections 1 and 2 only**: select from the top of the file down to the line
`-- >>> Now upload ...`, then press **Ctrl + Enter** (runs the selection).
Expect: `File format OFF_TSV_FORMAT successfully created` and `Stage area OFF_STAGE successfully created`.

### 3. Upload the file to the stage
1. Switch role to **LOADER** (or SYSADMIN): click your name bottom-left → Switch Role.
2. Left menu: **Data → Databases** (or Catalog → Database Explorer) → `GODESI_RAW` → `OPEN_FOOD_FACTS` → **Stages** → `OFF_STAGE`.
3. Click **+ Files** (top right).
4. Click **Browse**, pick `D:\go_desi\data\raw\off_india_raw.tsv.gz`, then click **Upload**.
5. The file appears in the stage's file list.

### 4. Check, load, verify
Back in the worksheet, run **sections 3, 4 and 5 one statement at a time** (click a statement, press Ctrl + Enter):

| Statement | Expected |
| --- | --- |
| `LIST @OFF_STAGE` | 1 row: `off_stage/off_india_raw.tsv.gz`, size about 8 MB |
| Peek `SELECT $1, $11, ...` | 10 rows of codes, product names, brands, dates |
| `CREATE OR REPLACE TABLE PRODUCTS` | Table created |
| `COPY INTO PRODUCTS` | status `LOADED`, rows_parsed 26293, rows_loaded 26293, errors_seen 0 |
| `SELECT COUNT(*) ...` | 26293 and 26293 |
| GoDesi products | 9 rows (Desi Popz, Kaju Katli, Ghee Mysore Pak, ...) |
| `COPY_HISTORY` | status `Loaded`, error_count 0 |
| TRANSFORMER count | 26293 (dbt's role can read the raw data) |

## Concepts in this step
- **Internal stage**: a storage area inside Snowflake where files wait to be loaded.
- **File format**: tells `COPY INTO` how to parse a file (delimiter, header, quoting, compression).
- **Querying a stage** with `$1, $2 ...` lets you inspect a file before loading it.
- **COPY INTO with a SELECT** adds metadata columns (`METADATA$FILENAME`, `METADATA$FILE_ROW_NUMBER`).
- **Load metadata**: Snowflake remembers loaded files for 64 days; running the same COPY again
  loads 0 rows (status `LOAD_SKIPPED`). Use `FORCE = TRUE` to reload on purpose.
- **Raw = untyped**: everything is `VARCHAR` here; types are fixed later in dbt staging models.

## Troubleshooting
| Problem | Fix |
| --- | --- |
| No **+ Files** button on the stage | Switch role to LOADER or SYSADMIN, refresh the page. |
| `Number of columns in file (x) does not match` | Make sure you uploaded `off_india_raw.tsv.gz`, not the `.csv`. |
| COPY returns 0 rows / `LOAD_SKIPPED` | The file was already loaded. Run `TRUNCATE TABLE PRODUCTS;` then the COPY with `FORCE = TRUE` added before `ON_ERROR`. |
| `Insufficient privileges` | First line of the worksheet must run: `USE ROLE LOADER;` |

# Phase 2b — Load the synthetic GoDesi sales data

Generated by `scripts/generate_synthetic_data.py` (fixed seed: rerunning gives identical files).
2 years of sales (Jan 2024 to Dec 2025) built around GoDesi's real products, in two batches:

| Batch | Covers | Load when |
| --- | --- | --- |
| `batch_1` | Jan 2024 to Nov 2025, order statuses as of 30 Nov | Now (`02_load_synthetic_batch_1.sql`) |
| `batch_2` | December 2025, later statuses for older orders, 5 price changes, 2 new SKUs | Phase 4, to test incremental models and snapshots (`03_load_synthetic_batch_2.sql`) |

Raw tables (all `VARCHAR`), 13 in total:

| Schema | Tables | Source system it imitates |
| --- | --- | --- |
| `ERP` | products, distributors, stores, promotions, invoices, invoice_lines | Company ERP + distributor sales to shops |
| `ECOM` | customers, orders, order_items, returns | GoDesi's own website (D2C) |
| `MARKETPLACE` | orders, order_items | Amazon, Flipkart, Blinkit, Zepto, Swiggy Instamart |
| `INVENTORY` | stock_daily | Warehouse stock in Bengaluru, Mumbai, Delhi |

Built-in patterns to discover later: Diwali, Holi and Raksha Bandhan spikes; July monsoon dip;
quick commerce growing ~2x a year; Ice Popz selling in summer and Chikki in winter.

Built-in data problems for dbt to catch: duplicate order rows, 5 order lines with a SKU that
doesn't exist (`GD-9999`), prices like `₹40.00` / `Rs. 40`, dates in several formats
(`2024-03-01 14:22:10`, `01/03/2024 14:22`, `2024-03-01T14:22:10+05:30`, `01-03-2024`),
upper-case Flipkart statuses, city spellings (Bangalore / Bengaluru / BANGALORE),
missing pincodes, SKU codes with stray case and spaces on quick-commerce platforms.

## Steps

1. **Snowflake:** open `load/02_load_synthetic_batch_1.sql`, select **section 1** (down to the
   `>>> Now upload` comment) and press **Ctrl + Enter**. Creates the file format and stage.
2. **Git Bash:** upload both batches (asks for account identifier and key passphrase):
   ```bash
   cd /d/go_desi
   .venv/Scripts/python.exe scripts/upload_to_stage.py data/raw/synthetic @GODESI_RAW.ERP.SYNTHETIC_STAGE
   ```
   Expect 23 lines ending in `UPLOADED`.
3. **Snowflake:** paste the whole `02_load_synthetic_batch_1.sql` and **Run All**
   (re-running section 1 is harmless).
4. **Check:** the last query lists all 13 tables; `actual_rows` must equal `expected_rows` on every line.

Do not run `03_load_synthetic_batch_2.sql` yet.
